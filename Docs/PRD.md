# ADHD 任务拆解与起步引导 APP (Project North Star) - 产品需求文档 (PRD)

> **版本**: v0.1 (Draft)
> **状态**: 规划中
> **作者**: Antigravity (协助 USER)
> **日期**: 2025-12-30

## 1. 产品概述 (Executive Summary)

**产品名称**: FocusFlow (暂定)
**核心价值**: 帮助 ADHD (注意缺陷多动障碍) 人群克服"执行功能障碍"，将压倒性的大任务瞬间拆解为可立即执行的微步骤，提供从"不知所措"到"开始行动"的助推力。
**产品定位**: 不是通用的待办清单 (To-do List)，而是**执行力教练 (Executive Function Coach)**。
**Slogan**: "Don't just list it, start it." (不仅仅是列出，而是开始。)

## 2. 用户画像 (User Personas)

### 核心用户: "挣扎的梦想家"
- **特征**: 18-45 岁，学生、自由职业者或创意工作者。高智商但低执行力。
- **痛点**:
  - **启动困难**: 面对"写论文"或"打扫房间"等模糊大任务时，感到瘫痪 (ADHD Paralysis)。
  - **时间盲区**: 无法准确预估任务耗时，经常拖延到最后一刻。
  - **工作记忆差**: 哪怕只有3步的操作，转身就忘。
  - **易受挫**: 传统 To-do 软件里堆积的过期任务带来巨大的羞耻感。
- **需求**:
  - "告诉我第一步做什么，别让我思考整个流程。"
  - 即时反馈和多巴胺奖励。
  - 极简、无干扰的界面。

## 3. 核心功能与 MVP 范围 (Feature Scope)

我们遵循 **"少即是多"** 原则，MVP (最小可行性产品) 仅聚焦于解决"启动难"这一最痛点。

### P0: MVP 核心功能 (Must-have)
1. **智能任务拆解 (Magic Breakdown)**
   - **输入**: 支持语音 (Whisper) 和文本输入模糊指令 (如 "我要准备明天的面试")。
   - **处理**: AI (LLM) 自动将其拆解为 3-7 个具体的、可执行的微步骤 (Micro-steps)。
   - **输出**: 带有时间预估的步骤列表 (例如: "1. 找出面试职位的JD - 2分钟")。
   - **交互**: 简单的"接受"或"调整"按钮。

2. **单任务聚焦模式 (Focus Mode)**
   - **单屏单步**: 屏幕上只显示当前正在进行的一步，屏蔽后续步骤干扰。
   - **视觉计时器**: 每一小步都有倒计时 (类似 Pomodoro)，直观显示时间流逝。
   - **下一步引导**: 完成后，通过极简动效滑向下一步。

3. **即时正反馈系统 (Dopamine Hits)**
   - **微交互**: 完成任务时有令人愉悦的音效和触觉反馈 (Haptic Feedback)。
   - **连胜记录 (Streak)**: 记录连续使用天数，鼓励每日启动。
   - **完成庆祝**: 任务全部完成后，全屏烟花或鼓励语。

4. **本地优先与隐私**
   - 历史记录本地存储。
   - 简单的统计概览 (今日完成任务数)。

### P1: 后续迭代 (Nice-to-have)
- **情绪检查站**: 任务开始前/结束后询问心情，记录情绪与执行力的关系。
- **个性化模型**: AI 学习用户习惯 (例如用户早上效率高，晚上效率低)，动态调整拆解粒度。
- **日历集成**: 将拆解后的任务块直接拖入 Google/Apple Calendar。
- **社区模板**: 分享"如何大扫除"或"如何报税"的拆解模板。

## 4. 技术架构建议 (Technical Architecture)

基于"快速验证、跨平台、低成本"的原则。

### 客户端 (Client)
- **框架**: **React Native** + **Expo**
  - **理由**: 一套代码覆盖 iOS 和 Android；开发速度快；生态成熟；支持热更新。
  - **UI 库**: Tailwind CSS (NativeWind) 或 Tamagui (兼顾性能与美观)。
- **本地存储**: MMKV 或 SQLite (WatermelonDB) 用于存储任务历史和用户偏好。

### 后端与 AI (Backend & AI)
- **API 层**: Serverless (如 Supabase Functions 或 Vercel Edge functions) 降低运维成本。
- **AI 模型**:
  - **首选**: 通用 LLM API (OpenAI gpt-4o-mini 或 Grok-beta)。
  - **Prompt Engineering**: 核心资产。需要精心调试 Prompt 以确保拆解的"颗粒度"适合 ADHD 患者 (不要太细碎让人烦，也不要太粗略没指导意义)。
- **语音转文字**: OpenAI Whisper API 或设备端原生语音识别 (节省成本)。
- **数据库**: Supabase (PostgreSQL) 用于由于认证和云端同步 (MVP 可先只做本地)。

## 5. UI/UX 设计原则 (Design Guidelines)

ADHD 友好的设计是产品的核心护城河。

1. **极简主义 (Clutter-free)**: 界面不能有任何非必要的元素。避免复杂的菜单和导航栏。
2. **色彩编码**:
   - 绿色/蓝色: 低压力、并在进行中。
   - 橙色/红色: 慎用，仅用于紧急提醒，避免引发焦虑。
3. **可触摸性**: 按钮要大，交互要有物理质感 (拟物化微交互)，让"点击完成"本身成为一种奖励。
4. **字体**: 选用易读性极高的无衬线字体 (如 Inter, Rounded Mplus)。

## 6. 上线与运营路线图 (Roadmap)

### 第一阶段: 验证 (Weeks 1-4)
- **目标**: 验证 Prompt 的拆解质量是否真的能帮到用户。
- **行动**:
  - 由于开发 App 需要时间，先用 **Telegram Bot** 或 **微信小程序** 原型进行测试。
  - 招募 20-50 位种子用户，收集真实的大任务案例，优化 Prompt。

### 第二阶段: MVP 开发 (Weeks 5-10)
- **目标**: 上架 App Store，核心功能跑通。
- **行动**:
  - 使用 React Native + Expo 开发。
  - 接入基础 LLM API。
  - 内部 TestFlight 测试。

### 第三阶段: 增长与优化 (Weeks 11+)
- **目标**: 留存率 > 30%，开始探索付费模式。
- **行动**:
  - 加入订阅制 (Freemium: 每天免费 3 个任务，订阅无限)。
  - 根据用户反馈迭代 UI。

## 7. 风险与对策 (Risks & Mitigation)

- **风险 1: API 成本过高**
  - *对策*: MVP 阶段限制免费用户每日次数；采用更有性价比的小模型 (如 Claude Haiku, Gemini Flash)。
- **风险 2: 用户流失快 (ADHD 特性)**
  - *对策*: 引入游戏化机制 (Gamification)；推送通知需要极其克制且"温柔"，避免让用户产生愧疚感进而卸载。
- **风险 3: 隐私合规**
  - *对策*: 尽量本地处理；上传云端的数据进行脱敏；由于不涉及医疗诊断，只需遵循应用商店标准隐私协议。
